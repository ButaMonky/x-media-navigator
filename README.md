# X Media Navigator — TypeScript rebuild (private beta)

> **2026-10-29 非公開QA v2.4.19**：FxEmbedの同意後ページ先読み、低画質仮表示・先読み通信の匿名診断ログ、ワンクリックQA更新を試験中。GitHubの公開main・安定Draft PR・通常インストール先は未変更。使い方は [FxEmbed QA診断と更新手順](docs/QA_FXEMBED_DIAGNOSTICS.md) を参照。プロジェクト直下の `Update-Chrome-QA.cmd` から更新する（Chromeカードの再読み込みは必要）。本番Xでの連続閲覧・視覚改善は未検証。


X (Twitter) プロフィールのメディアタブから開いた画像・動画を、一覧順に移動する非公式Chrome拡張機能の開発版です。

**状態:** TypeScriptリファクタリングの検証ブランチ。**X実サイトでの動作確認が済むまでリリース不可**。既存のChromeウェブストア版は書き換えません。

## 操作

| 操作 | 挙動 |
| --- | --- |
| `→` | 投稿内に次の画像があれば **X標準の画像送り**。確認できた**最後の画像**からのみ次の投稿へ進む |
| `←` | 投稿内に前の画像があれば **X標準の画像戻し**。**最初の画像**からのみ前の投稿へ戻る |
| `Shift + ← / →` | 拡張による特別な移動はしない（統一した左右キー操作） |
| 画面上の `◀` / `▶` | 常に前後の**投稿**へ移動する専用ボタン |

**先読み:** メディアビューア表示中、既に一覧で確認できた次の写真・複数の次投稿を最大5画像までX公式の画像CDNから低優先度で先読みします。**同時通信は2件まで**で、3G・低メモリ端末では2画像まで。動画の全量先読みや外部API呼び出しはしません。省データ設定・2G・オフライン・非表示タブでは追加先読みを停止します。画像は `decode()` の完了後のみ視覚引継ぎに利用し、概算80MiBを超える巨大画像はキャッシュしません。X実際の表示URLと一致してキャッシュが再利用されるかは実機検証が必要です。

**SPAとの違い:** XはすでにSPAです。今回行うのは画像のプリロードで、ビューアを閉じて次の投稿を開き直す瞬間の再描画まで消すものではありません。React内部の未公開APIに割り込まない設計です。

**右キーの安全判定（v2.4.x）:** Xの画像カウンター、カルーセルの明示的な画像総数・位置、写真専用の無効化されたネイティブ送りボタン、添付画像4枚上限を根拠に終端を判定します。2026年のカルーセルでは見えている1〜3枚が全画像とは限らないため、**可視サムネイル数だけで終端を決めません**。総数が不明な場合はXの標準画像送りを先に試し、未移動時は追加の→確認が必要になる場合があります。確定済みの総数は同じセッションで再利用します。

**メディアタブ（v2.2）:** `?filter=photo` と `?filter=video` 等を別の一覧として扱います。XのSPAが新タブのDOMを置き換えるまでは古い一覧を新しい一覧と混ぜず、移動を一時停止します。勝手なフィルター切替は行いません。通常時の全件走査はMutationObserverに任せ、450msの確認ごとに全タイルを走査しません。

`/ユーザー名/media` の一覧から開いたビューアでのみ動きます。別プロフィールの投稿や通常の投稿ビューアでは勝手に動きません。

## v2.4.0 高速化ベータ（2026-10-26）

- 画像の先読み候補を最大5件まで増やしつつ、同時ネットワーク要求は最大2件に制限。3G/省メモリ環境は2件、Save-Data・2G・オフライン・非表示タブでは追加取得しない。
- デコード済み画像の短期キャッシュは最大6レコード、概算80MiBを上限に管理。再訪時の再ダウンロードを減らし、失敗URLの無限再試行も防ぐ。
- 投稿切り替え時の引継ぎ表示は画像エリアを優先して覆い、Xの新しい画像が読み込み済みと確認できるまで解除しない。最大1.8秒の安全タイムアウト付き。
- 完全なSPA切替（右側のツイート欄を閉じずに次投稿を表示）は未実装。現状の閉じ→開き直しに由来するアニメーションは残りうる。
- Xの最新カルーセルで、画面に1〜3枚しか見えていないことを「全部」と決める判定を廃止。ARIA画像カウンター、明示的に無効化されたネイティブ送りボタン、4メディア上限から終端を判断。
- 一度確定した投稿の画像総数はセッション内で最大128件保持。初見の投稿で十分な情報がなければ右キー2回の安全な確認方式を維持する。
- 詳しい根拠と検証状況：[v2.4.0 研究レポート](docs/research/2026-10-26-fast-gallery-v240.md)。GitHub Actions/模擬ChromeテストとX実機での速度改善は区別する。

## v2.4.1 起動検出・キャッシュ安定化（2026-10-26）

- XのモーダルをDOM追加・除去から検知し、既存の450ms定期監視より早くビューアを捕捉。Xの非公開ルーターや履歴APIをフックしない。
- ビューア検出後の350msの先読み開始待ちを撤廃し、次のタスクで画像リクエストを準備。
- 1枚で概算80MiBを超える巨大なデコード画像は短期キャッシュせず、繰り返しの再ダウンロードも抑止する。
- 画像エリアの座標を確認できない場合は視覚引継ぎを停止し、右の投稿欄を黒い全面レイヤーで覆わない。
- コード・テストの詳細：[研究レポート](docs/research/2026-10-26-prefetch-startup-v241.md)。**Xの実サイトにおける高速化率、右側投稿欄の開閉アニメーションの根本解決は未検証／未達です。**


## v2.4.3 — 長いメディア一覧での不要な再走査を削減

- サムネイルの`src/srcset`が変わった場合は、更新された**1タイルのみ**を検査。全体の並びや所有者に関係するDOM変更の場合だけ一覧全体を再走査します。
- 同じ画像URLをキャッシュに重複登録し直す処理を廃止し、画像が実際に入れ替わったときだけ先読み候補を更新します。
- 100ms以内に「画像URL変更」と「新しい投稿タイル追加」が重なった場合は、競合しないよう全体スキャンへまとめます。
- 画像5件までの先読み、同時通信2件、低速回線制限、SPA画像引継ぎ、右キーの安全判定は変更しません。
- 技術的な記録は [v2.4.3の研究資料](docs/research/2026-10-26-targeted-media-source-v243.md) に保存しています。X本番のCPU改善や通信量は未測定です。


## v2.4.4 — 高速な投稿切替でも先読みが止まらないよう改善

- 前の投稿で始まった**不要な進行中画像取得を中断**し、新しく必要になった写真に最大2件の通信枠を優先して渡します。表示中のSPA引継ぎ画像や、既にデコードされた短期キャッシュは維持します。
- 画像の読み込み・デコードが止まった場合は12秒で処理を解放し、次の画像を読み込めるようにします。離れたメディアタブの未完了先読みは中断します。
- 遅延表示時に`currentSrc`がプレースホルダーでも、`img.src`に妥当なX画像CDN URLがあれば先読み候補として利用します。第三者ホストへの画像取得は認めません。
- 先読み最大5件／同時通信2件／省データ・低速制御は据え置きです。**X実サイトでの速度改善率、右側投稿欄の開閉アニメーションは依然未検証・未解決**です。
- 根拠・検証と今後の調査は [v2.4.4研究資料](docs/research/2026-10-26-stale-prefetch-v244.md) に記録しました。

## v2.4.5 — シームレス引継ぎ時の写真識別・デコード待機

- Xが新しいモーダルを描画するとき、アバターや別の写真が先にロードされても、**次に表示する写真そのもののCDNメディアID**が一致するまで視覚的引継ぎを解除しません。
- Xが異なるサイズ（`name=large`・`name=orig`）のURLで同じ画像を表示する場合にも、同じメディアIDとして判定します。先読みが実際のブラウザキャッシュへ命中したと断定するものではありません。
- 正しい写真が読み込まれていても`decode()`が利用可能なときはデコード完了を待ちます。古い画像の非同期デコードが遅れて完了しても、新しい投稿を誤って表示完了にしない処理を追加しました。
- 操作・追加通信・権限の変更はありません。引継ぎの最大1.8秒タイムアウトは維持し、右側投稿欄の再表示アニメーションもまだ根本的には残ります。
- 調査根拠：[v2.4.5 SPA画像ID・デコード研究](docs/research/2026-10-26-photo-identity-handoff-v245.md)。**X実サイトでの効果は未検証**です。

## v2.4.6 — 読み込み時の表示乱れ・左右キーの再検討（2026-10-26）

v2.4.5の実機報告を受け、**先読み画像の黒い背景や画像のはみ出しをなくし、ビューアを閉じた後だけ引継ぎ画像を表示する**ように修正しました。

- 左キー：1枚目からの前投稿への移動は、一般的なPreviousボタンに邪魔されず1回で行う。
- 右キー：枚数が不明な写真はまずX本来の右キーへ通し、約1050ms後も**表示中の写真・URLが同一で読み込み済み**、後続画像が既知でない場合などに、追加押下を求めず次投稿へ自動移動する。
- 写真判定：画面の大きな主画像を優先し、別サムネイルの更新でXの画像送りが成功したと誤判断する問題を避ける。候補が曖昧・写真未ロード・進行中表示があれば勝手に投稿を飛ばさない。
- **制限：** 枚数が不明な投稿では、一定時間反応がないことは最終画像の絶対的証明ではない。Xの反応が著しく遅い場合の誤移動の可能性を実機QAで検証する必要がある。
- [詳細な研究レポート](docs/research/2026-10-26-one-press-visual-stability-v246.md)。**X実サイトでの改善確認はまだ行っていません。**

## 開発・テスト

Node.js 20以上が必要です。

```sh
npm install
npm run build
npm test
npm run check
```

Chromeの拡張機能として読み込むのは **`extension/`** です。TypeScriptファイルを直接読み込むことはできません。
開発版をテストするときはChromeの「デベロッパーモード」から「パッケージ化されていない拡張機能を読み込む」を選択してください。**元のストア版は一時的に無効化**してください。

`XMN_RUN_CHROMIUM=1 npm run test:browser` は、Chromiumが利用できる環境でのみ動く任意の擬似X統合テストです。Xの実サイト検証とは異なります。

## 維持すべき原則

1. TypeScriptを単一の開発正本とし、`extension/content_script.js` は毎回ビルドで更新する。
2. Webストア版の原本とChromeのプロフィールは書き換えない。開発ベータの固定フォルダだけ、検証済みの変更を同じパスに反映する。
3. 動作していない機能を「修正済み」とせず、静的証拠・自動テスト・X実機確認を分ける。
4. 追加権限や閲覧履歴の保存は行わない。先読みは既存のX公式画像CDNのみを対象とし、外部の開発者サーバーには送信しない。
5. Firefox側のMIT表記とChrome配布物の権利関係を確認するまで第三者公開しない。

初期解析: `docs/analysis/baseline-v1.3.md`。今後の機能案は `docs/IDEAS.md`。
