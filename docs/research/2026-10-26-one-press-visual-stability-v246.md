# X Media Navigator v2.4.6 — 実機報告を受けた表示乱れと左右キー再設計

日付：2026-10-26／基点 v2.4.5 commit 537da69／非公開開発ブランチ fix/one-press-visual-stability-v246

## ユーザーからの実機報告（LIVE USER REPORTED）

v2.4.5において、**読み込み時に毎回表示が少し乱れること、左・右キーを2回押さないと投稿間移動ができないこと**が報告された。模擬Xテストの成功は実サイトでの成功を保証しない。ログイン済みのX実DOMには現在ブラウザ接続からアクセスできていないため、根本原因のうち構造として証明できるものと仮説を区別する。

## AUD-044：引継ぎ時の黒い背景・画像の切り取り（SOURCE VERIFIED / CODE FIXED）

- v2.4.5の`.xmn-visual-handoff`は黒背景（`background:#000`）で初期表示され、次の投稿をクリックする前に別の画像レイヤーをDOMへ追加していた。X本来の画像の上に二重の背景が描かれ、表示に段差やちらつきが起こり得る。
- 新版では背景を透明化し、DOM追加直後は`opacity:0`。X標準ビューアの終了を確認した後、次投稿へリンクをクリックする直前に`xmn-handoff-visible`を付ける。
- 先読み画像のサイズ制限が従来`max-width:100vw/max-height:100vh`だったため、画像領域だけに制限した狭いホストで大きな画像を切り取る可能性があった。`max-width/height:100%`とし、画像領域内に収める。
- これはあくまで短い視覚的引継ぎ。X本来のモーダルを閉じ再オープンするため、右側の投稿・返信欄の開閉アニメーションを消したわけではない。
- Node CSS/順序テスト、Chromeの合成DOMで背景色・クリック非阻害・表示タイミング・最後の画像への移動を検証。

## AUD-045：左キーの境界を曖昧なネイティブ操作で阻害（SOURCE VERIFIED / CODE FIXED）

- `/photo/1`はその投稿の最初の写真であるため、一般の`Previous`ボタンが存在しても、投稿間の左操作を保留する必要はない。
- 1枚目の左キーは、前の投稿がメディア一覧で見つかり安全にクリック可能なら、**1回で前の投稿**へ進む。
- 一般的な`Next`/`Previous`ラベルをXの写真送り専用ボタンと混同しないよう、写真や画像に言及するラベルだけを認識する。動画のキー操作・入力欄・修飾キーは従来どおり除外。

## AUD-046：画像枚数不明時の右キー2回要求（SOURCE VERIFIED / CODE IMPLEMENTED）

- 旧コードには`pendingRightConfirmation`で1回目を確認し、2回目で次の投稿へ移動する分岐が存在していた。
- 新方式は**最初の1キーをXネイティブへ通す**。1050msの観測時間を設け、URLと実際の表示写真が同一、写真がロード済み、進行中を示す`aria-busy`や`progressbar`がなく、写真専用の次ボタンが有効ではなく、一覧中に同じ投稿の後続`/photo/N`も確認できない場合のみ、2回目を要求せず次投稿へ自動移動する。
- 事前に分かっている複数画像の途中、Xが画像を変更した場合、画像の読み込み中・写真が未表示・判定が曖昧な場合は勝手に投稿を飛ばさない。従来の明示カウンター・ARIA・4枚上限の確定情報があればこちらを優先する。
- **重要な限界：** 1050ms間Xが無反応という観測は、厳密な意味で「最後の画像」の証明ではない。Xが著しく遅く、まだ次の写真の状態をDOMに反映していない場合、誤スキップの可能性を完全には排除できない。実機QAで失敗があれば、観測時間や条件を再検討し、写真を飛ばさない方針を優先する。

## AUD-047：複数画像が混在するビューアでの写真特定（SOURCE VERIFIED / CODE FIXED）

- 旧版はビューアの全`img[src]`の内容を1つに連結して比較しており、引用画像や別のサムネイルが変わっただけで「Xが画像を進めた」と誤認し、右キー1回移動を中止する可能性があった。
- 新版ではブラウザから見える画像領域が明確な場合、面積が大きく表示されている写真を代表とする。2画像の大きさが近く識別できない場合、ロード済みでも自動移動はしない。1枚だけで明確な場合はサイズを理由に拒否しない。
- `currentSrc`と`src`の両方を監視するが、選ばれた画像リソースのURLは取得成功を示すものではない。別メディアIDを選択中だったり`complete`がfalse、`naturalWidth`がゼロの場合は画像未準備扱い。
- `aria-busy=true`や`role=progressbar`が画像ビューアに存在する場合は読み込み途中の可能性があるとして右キー自動移動を保留。

## 検証・残課題

- TypeScript型検査・Node/FakeDOM・Chromeヘッドレスの合成Xは成功。画像未準備・途中の後続画像の存在・複数候補・一般ボタン・入力欄・リソース遅延等を追加試験。
- **実サイトXの左右キー操作と表示乱れの改善はユーザーによる再確認が必要**。このレポートでは実機成功・速度向上の測定値を主張しない。
- 今後の優先事項は、X実サイト上でDOMの写真総数を安全に判定する情報源を確認すること、右投稿欄の再生成を伴わない移動方式を検討すること、先読みURLと実表示URLのキャッシュ一致をDevTools Networkで測定すること。
- Chromeウェブストア版・mainは未変更。権限追加、React/History/認証への直接介入、定期同期アプリは導入しない。
