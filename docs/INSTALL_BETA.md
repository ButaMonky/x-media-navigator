# X Media Navigator — 固定フォルダのインストールと更新（v2.4.4）

> 非公開のChrome拡張開発版です。X実サイトでの速度効果は未検証。旧Web Store版を変更しません。

## 初回導入（1回だけ）

1. Chromeのテスト用プロフィールで `chrome://extensions` を開く。
2. Web Store版または旧ベータを同じプロフィールで二重有効化しないよう無効化する。
3. デベロッパーモードをオンにし「パッケージ化されていない拡張機能を読み込む」を選ぶ。
4. フォルダ `%USERPROFILE%\Downloads\X-Media-Navigator-Current` を読み込む。
5. `X Media Navigator (TypeScript Dev)` のバージョンが **2.4.4** と表示されるか確認。

## 今後の更新

- 私が依頼された修正を実装・テストし、GitHubの開発ブランチへコミット/Pushした後、成功したコードを**同じ固定フォルダの6ファイル**へ反映します。
- Windowsの定期タスク、バックグラウンド更新プログラム、追加サービスは作成・使用しません。
- Chromeでその拡張カードの**再読み込み（⟳）**を押し、既に開いているXのタブも更新してください。
- Chromeのページ上部の「更新」ボタンだけでは非公開GitHubからファイルを取り込みません。
- PCがオフラインの場合はGitHubへの保存を先行し、PC側は未同期として明示します。

## v2.4.0の主な変更

- 既知の画像を最大5件先読み（同時リクエストは2件まで）し、解像済み画像の短期キャッシュを管理。
- 次画像と別投稿の表示引継ぎを、実際のX新画像が表示可能になるまで継続。ただし最大1.8秒で後片付け。
- フォルダ内の画像が1〜3枚だけ表示されても総数とは断定せず、明示カウンター・ARIA・標準画像送りボタンなどから判定。
- 一度確認した最終画像番号をセッション中に記憶。確実に分からない初見投稿では誤スキップ防止の二度押しが残る場合があります。
- Xの右側投稿欄が閉じて再表示される問題は、ネイティブモーダルを開き直す方式を使うため完全には未解決です。

検証項目は [QA_BETA_V240.md](QA_BETA_V240.md)、根拠・設計は [v2.4.0研究資料](research/2026-10-26-fast-gallery-v240.md)。

## バックアップ・復旧

問題が起きたら `chrome://extensions` でベータを無効化してください。旧バージョンのバックアップがある場合は、Chromeを再読み込みする前にその6ファイルを固定フォルダへ戻せます。旧Web Store版を修復したり、Chromeプロフィールや認証情報を変更する必要はありません。

X本番のDOM・先読みキャッシュ効果・描画速度を測る際にCookieや認証ヘッダーを保存・公開しないでください。
