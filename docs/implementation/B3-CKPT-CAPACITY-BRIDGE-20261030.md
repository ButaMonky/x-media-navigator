- すでに主開発に取り込まれたProvider IntegrityのUTF-8 4MB判定と
  B4 Data Saver/offline時の転送中断、B5実Chrome必須CIを維持。

## 解消した無駄な外部通信と誤案内

1. B2に保存済みの**次ページ**がある状態で再度右矢印を押すと、
   再度FxEmbedへページ取得を試み、保存済み状態と衝突する可能性があった。
   検証済みmanifestからactivePageを照合し、次ページがすでに
   確定しているときはAPI通信と保存操作を行わない。
2. B2が**最大64チェックポイントページ**を保持した場合、
   これ以上格納できないのに右矢印で外部APIへ繰り返し問い合わせ、
   レート制限や電力・ネットワークを無駄にする可能性があった。
   保存上限到達時はAPI通信前に拒否し、ローカル容量上限と
   外部API自体の投稿終端を混同しない。
3. manifestの非同期確認中にユーザーが別投稿・別プロフィールへ
   移動した場合は旧世代の取得処理を開始しない。
   manifest自体が欠落・不一致なら信頼できる継続経路はないため、
   Xの表示を維持して安全側で停止する。
4. 上限・保存済み隣接ページの状態をUI案内で区別し、
   無意味な再試行を繰り返さない。
5. ウォームアップは保存済みページに当たった後、同じカーソルで
   再取得を連発しない。プロフィール／セッションリセットでは
   ローカル停止フラグも消し、新しい閲覧を妨げない。

## 出典の採用範囲

- B3の保存ページ上限・再取得停止・generation確認と関連試験を導入。
- 元B3の`readBoundedPublicBody`の手動UTF-8カウントは再移植**しない**。
  開発正本にはProvider Integrityが導入した`TextEncoder`ベースの
  4MB厳格判定がすでに存在し、同機能の二重実装は避けた。
  代わりにB3のUTF-8／境界値／サロゲート検証5件を読み取り専用で移植し、
  既存の正本実装の正確性を確認した。
