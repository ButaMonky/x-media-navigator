## 修正1：外部APIが異常な投稿を無言で除外してカーソルを進める

- `src/core.ts:parsePublicMediaPage`は、ユーザー本人の投稿に
  写真と動画が同時に含まれた場合や、写真のURLが不正な場合、
  その投稿だけ`continue`で捨てていた。
- 返却された`cursor.bottom`を信頼してさらに次ページを読むと、
  **間に存在した投稿を一度も表示しないまま飛び越える**危険がある。
  これはユーザーが重視する「28を超える番号を確実に続ける」に反する。
- 新規のRED試験で「400→混合300→200」のページから300だけ消え、
  200まで索引化されることを確認した。
- 修正：投稿者が対象プロフィールで、媒体があると判明した場合は、
  不正・混合・5添付超・重複投稿ID・不正CDN／投稿URLを**ページ単位で拒否**。
  番号や動画URLを創作しない。カーソルを先に進めない。
- 異なる投稿者の投稿や、媒体が存在しないことが明白なテキスト投稿は
  従来どおり除外できる。正常な写真・単一動画・`animated_gif`の
  パーサーを維持。RED→GREEN試験2件と既存契約の厳格化を確認。
## 修正2：非ストリームAPIの4MB上限がUTF-16文字数で判定されていた

- `src/content.ts:readBoundedPublicBody`の`response.body`が無い
  互換経路は、JavaScriptの`text.length`（UTF-16コード単位）と
  転送上限4,000,000**バイト**を比較していた。
- 例えば`€`の150万文字は150万コード単位でもUTF-8では450万バイト。
  従来はサイズ超過の外部JSONを通していた。
- 新規RED→GREEN検査で、UTF-8の実バイトを
  `TextEncoder`で判定。コード単位ですでに上限超過なら
  先に短絡して追加の大きなメモリ割り当てを避ける。
- ちょうど400万バイトの多バイト文字列は許可、
  400万バイト超は拒否する。既存のストリーム読み取りは
  バイト累積上限を保持し、超過時に`cancel`・`releaseLock`
  を呼ぶ試験を追加。
- テストの隔離VMにもブラウザ標準の`TextEncoder`と
  `TextDecoder`を注入し、互換経路の現実に近い動作を評価。
  標準APIが無いことによる初回単体試験失敗は修復済み。
