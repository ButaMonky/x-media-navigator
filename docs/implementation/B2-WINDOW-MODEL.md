## 追加したロジック

`MediaPostGroup`は投稿ID、正規化済みメディア参照、来歴（XのDOM／FxEmbed／復元／混合）、証拠の完全性（complete/partial/unknown）を保持する。

`groupMediaRefs()`は投稿IDの連続グループを作り、同じ投稿が離れた位置へ再登場する場合を拒否する。`prependNativeGroups()`はXの一覧先頭への新着投稿追加を前方へ保持し、本文の既存順序を壊さない。`appendVerifiedPublicGroups()`は検証済みのAPI続きページだけを追加し、最後のネイティブ投稿に未登録画像がある場合はその投稿内へ統合する。既に完全と証明されたネイティブ投稿へ外部APIが余分な添付を加えた場合は拒否する。

`ValidatedMediaWindowIndex`は投稿系列を最初に一度検証し、投稿ID→位置のマップを保持する。以後の`select()`は最大450メディア参照の前後ウィンドウだけを歩き、**6000投稿の索引全体を毎キー入力で再検査しない**。出力は防御的コピーで返し、原本の投稿・アルバムを分割しない。

## 正式統合前の制限・依存関係

- **未組込**：Content Scriptの`Controller.refs`や`scanTiles()`はまだ既存設計のまま。今回の独立モジュールだけでX実サイトの不具合が修正されたとは主張しない。
- `checkpointVerified`は呼出側が正しいAPIの継続カーソルを検証済みであることを表す。モジュール自体はFxEmbedへ通信せず、第三者APIの真正性を証明しない。
- ネイティブDOM順序と外部APIの降順は同じものと仮定しない。現行のXサイトに対応する全フィルター、引用、リポスト、画像／動画混合、非公開・削除投稿は実機で未確認。
- `ValidatedMediaWindowIndex`の450参照制限は**画面近傍の取り出し範囲**であって、バックグラウンドの全投稿情報を450件に限定する仕組みではない。実メモリを減らすには、別途チェックポイント付き退避・復元の設計が必要。
- B3の左右キー、API処理、旧X DOMの世代管理との統合は、担当開発の既存ブランチが安定した後にのみ行う。別ブランチを無条件にfast-forwardで統合できるとは限らない。
- 通常Chrome・非公開QA固定フォルダ・main・Draft PR #17へは反映しない。
