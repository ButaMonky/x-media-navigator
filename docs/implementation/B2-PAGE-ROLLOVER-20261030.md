## 今回追加した処理

1. 既知の新→古順・同一Xプロフィール・実メディアの参照を持つ
   FxEmbedカーソル取得結果を、**投稿グループ単位**で検証する。
   取得不能／混合・重複／欠けたアルバム／不明な画像URLは推測しない。
2. 現在の参照数＋APIで検証した追加数が450を超えるとき、
   これまでの`index_limit`停止の代わりに、
   検証済みWorker短期セッションを**ページ0の不変スナップショット**として保存。
3. 追加候補を最大450メディア参照の**別の完全投稿ページ**として保存。
   2つのスナップショット／元カーソル／新カーソル／投稿順が検査された後に、
   `manifest.put`で初めて公開状態とする。途中失敗なら旧画面と索引を維持。
4. 既存manifestの末尾ページから次のカーソルを取った場合も、
   既に確定済みのページを書き換えず**次のページを追加**。
   Xの通常ページ遷移後のみ`manifest.activate`でアクティブページを更新。
5. 保存済みページへの右/左移動ではWorkerが正確なURLを返し、
   URL・送信元・本人同意・カーソル・写真群・時系列を確認する。
   ページ間でReact SPAを偽装せず、返信欄の実X保持は未保証。
6. 並行した古い文書の`session.set`が新しいアクティブページを
   上書きしないよう、manifest処理と同じWorkerロックに統合。
   ページ内容が同一で期限時刻だけ新しくなった書込は
   **成功と応答しても保存内容や有効期限は変更しない**。
   これにより古いタブ処理から30分の期限を延ばさない。

## 失敗・未実装・厳密な上限

- 新コードを既存テストへ初めて接続すると、
  `restoredCheckpointPage`未設定の合成フィクスチャが
  `undefined !== null`で拒否された。実コードではnullだが、
  既存契約を壊さないようnullish判定に修正し全回帰を通過。
- テスト用一時スクリプトのサーバー文字列に
  エスケープされた改行が残り、Node構文エラーで停止。
  **元ソースを変更せず**テストハーネスだけ修正してMV3実験PASS。
- manifestの初回生成には以前のWorkerで保存済みの
  **APIカーソル付き完全な短期セッション**が必要。
  まだAPI未取得の巨大Xネイティブ一覧のみではページを勝手に生成しない。
- 単一API応答に450参照を超える完全な添付が含まれる場合、
  不完全に切り捨てず安全停止。合計**最大64ページ、
  各450参照以内、保存の有効期限は元ページから約30分**。
- FxEmbedとX公式メディアタブの投稿網羅／正確な順序が
  恒久的に一致する保証はない。実Xでの28→29件目、動画・GIF・混合、
  返信パネル、描画品質、速度、URLの挙動は未受入。
- 拒否や接続断で代替API・Cookie・非公開GraphQL・安全制限を迂回しない。
  完成扱いや公開作業は行わない。
