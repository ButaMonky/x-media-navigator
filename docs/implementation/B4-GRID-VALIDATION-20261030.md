## R-043：一覧の中間だけが変わるフィルター切替

- 旧`captureGrid()`/ `hasGridTurnedOver()`は先頭8・末尾8と
  件数・親カラムだけを比較。Xが中間のタイルだけ別投稿に差し替えると
  `pendingGrid`が残り、次の媒体リストを読み込めない。
- **3つのRED回帰試験**：同一DOM中間リンク差し替え、
  中間DOM要素そのものの差し替え、300タイルの無変更→中間変更。
- **修正**：フィルター切替中だけ、全タイルのDOM IDと正規化した
  媒体キーの**順序付きスナップショット**を取得。先頭と末尾が同じ
  場合も中間の1件差分を検出。未変化ならfalseを返す。
- 無関係な450msアイドルポーリングで全媒体キーを毎回取得する
  動作は追加せず、切替待機時の一時監査に限定する。
## R-042：先頭投稿が仮想化で消えたときの誤った末尾追加

- 元索引400/300/200のうち、Xが400を仮想化でDOMから外し
  新しい500を先頭に挿入すると、旧コードは「既知の最初の要素が
  0番のときだけ先頭に挿入」のため500を**末尾へ誤追加**した。
- **4つのRED回帰試験**：既知先頭欠落での新着投稿500、
  中間に現れた証明できない350、全件不明で既知アンカーなし、
  新着候補が逆時系列で並ぶ600/500。
- **修正**：最初に見つかる既知DOM参照がindex0でなくても、
  未知の先頭投稿群が旧先頭より厳密に新しく、
  並びが投稿単位で降順かつ矛盾しない場合だけ先頭へ追加。
  途中の投稿や全件不明など位置を証明できない先頭参照は
  **末尾へ無条件追加しない**。既知の投稿順・矢印を維持。
- 従来の「単独メディアリンク優先」試験は、関連のない旧索引を
  引き継いで400を末尾追加する前提を持っていた。リンク所有権
  単独検証を新しい空索引から行う形に分離し、
  UI操作中の誤ソートを許容しない。
## B4 独立ブラウザ性能測定（合成データのみ）

- 新規`tools/b4-grid-performance.mjs`と`npm run test:b4:grid`。
  一時Chrome for Testing／localhostページを利用。
  外部ネットワーク、Xログイン、個人Cookie、保存済み
  Chromeプロフィールを使わない。
- 1200タイルの初期バッジ1200件を検証。中間href変更・DOM差替は
  どちらも検知。15回サンプリングで指紋比較中央値約7.5ms、
  最大約12.2ms（今回の参考測定）。
- `XMN_B4_TILE_COUNT=3000`でも、バッジ3000件と
  中間差分の検知を確認。15回中央値約20.7ms、
  最大約31.2ms（同環境・同条件の参考測定）。
- ローカル合成測定は**実X上の描画遅延や通信速度を保証しない**。
  時間はPC負荷・ブラウザ環境によって変動し、絶対上限と扱わない。
