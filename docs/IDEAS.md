# 利便性改善案（優先度・保守性・安全性を重視）

v2ではまず「X標準の操作を壊さず、正しいメディア一覧へ移動できる」を完成させる。便利機能は一度に足し込まず、個別の実装と回帰試験を条件に採用する。

| 優先 | 機能案 | 効果 | 先に解決すべきこと |
| --- | --- | --- | --- |
| P0 | **キーボード操作の設定** | Shift+左右などのキー割り当て・無効化を選べる | 既存ショートカットや動画と競合しない検証 |
| P0 | **移動先を明確に表示** | 「投稿内 2/4」「一覧 18/80」などを区別 | X実際のメディア枚数を確実に検出 |
| P1 | **閲覧位置に戻る** | ビューアを閉じても一覧の位置を保持 | SPA履歴・スクロール位置の検証 |
| P1 | **移動中・追加読み込み中の表示** | 読み込み中/最後の項目/移動不能の区別 | 誤った『最後』判定を回避 |
| P1 | **画像・動画別の一覧フィルター** | 大量のメディアの探索が容易 | X DOMに依存し過ぎない型検出 |
| P1 | **番号指定ジャンプ** | 一覧の特定番号へ一発移動 | 遅延ロード・仮想リストに対応 |
| P2 | **ホバー時だけ操作ボタンを表示** | X標準の操作を隠さない | タッチ・キーボード利用時のアクセシビリティ |
| P2 | **連続画像の自動送り（オプトイン）** | 最終画像から次の投稿へ進める | 画像末尾を正確に識別、デフォルトOFF |
| P2 | **セッション内の閲覧済み表示** | 長いメディア一覧で重複閲覧を防止 | 保存なし・消去可能なセッション内情報で実装 |
| P3 | **サムネイル帯・一覧ミニマップ** | 前後の画像を視覚的に探せる | パフォーマンス・メディア取得・UI競合対策 |

## 推奨する実装順

1. 今回のTypeScript v2の実機安定化。未検証のUIに新機能を重ねない。
2. 操作設定と表示情報の分離（ショートカットやボタンの設定を小さく追加）。
3. 一覧位置・読み込み状況・ジャンプ機能。
4. 一覧フィルターとサムネイルの付加機能。

## やらない方がよいもの

- Xのページ外へ勝手に遷移する操作や、推測URLへの自動ジャンプ。
- 画像や閲覧履歴の外部サーバーへの自動送信。
- DOMの個別セレクタごとに大量のサイト専用パッチを積み重ねる設計。
- 動作や挙動をユーザーが理解できない強制自動送りをデフォルトONにすること。

注: これは提案段階。採用・実装済みという意味ではない。
