# v2.4.33 x-web media grid recognition (private QA)

## Symptom

On the 2026-11 X web client (`abs.twimg.com/x-web/...`, Relay GraphQL on `api.x.com/graphql/.../UserPhotoTimeline`)
the extension did nothing. v2.4.32 verbose diagnostics on a real profile media tab reported:

- `healthCode: "MEDIA_GRID_NOT_FOUND"`, `indexedRefs: 0`
- `listItems: 0`, `primaryColumn: 0`, `cellInnerDiv: 0`, while `mediaAnchors` > 0

## Cause

The new grid markup (from the server-rendered HTML of a real `/<user>/media?filter=photo` page):

```html
<main>
  <div id="urt:photos:<user>">
    <ul><li data-index="0">
      <div role="list" class="grid grid-cols-3 ...">
        <div role="listitem">
          <div role="link" data-href="/<user>/status/<id>">
            <a aria-hidden="true" href="/<user>/status/<id>"></a>
            <a aria-label="メディアを表示" href="/<user>/status/<id>/photo/1"><img ...></a>
```

- Items are `div[role=listitem]` (old: `li[role=listitem]`); there is no `data-testid="primaryColumn"`.
- The grid is hydrated/streamed after `document_idle`. The MutationObserver only triggered a rescan
  when an added node was/contained `li[role=listitem]`, so the late grid was never scanned.
  (A static scan of the same HTML indexes fine; a simulated late insertion reproduced `MEDIA_GRID_NOT_FOUND`.)

## Fix

- Accept `div[role=listitem]` as a media tile (`MODERN_TILE_SELECTOR`, `closestTile()`), including
  live-link lookup used for post-to-post navigation and click-time prefetch.
- Rescan when added nodes contain a modern tile or any `/status/` link.
- While nothing is indexed on a media route, retry the scan at most every 1.5 s.

## Verified here

- `npm test`: 374 pass / 0 fail / 6 skipped.
- jsdom simulation with the real SSR grid HTML inserted 800 ms after startup:
  v2.4.32 → `MEDIA_GRID_NOT_FOUND`, 0 badges; v2.4.33 → `MEDIA_INDEX_READY`, 20 badges.
