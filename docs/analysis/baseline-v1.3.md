# v1.3 静的解析レポート（2026-10-24）

対象: `upstream/chrome-v1.3/content_script.js` (502行)、`style.css`、`manifest.json`。
証拠分類: **SOURCE VERIFIED** = 配布コードの記述を確認、**RUNTIME NOT VERIFIED** = X実サイト上で未再現。

## 確定した原因

### AUD-001 / P0 — 左右キーがXの画像送りを奪う (SOURCE VERIFIED)
- 行398以降の `handleKeyDown()` は `keydown` をキャプチャ段階で受ける（行222付近）。
- 右矢印キーの処理は `preventDefault`・`stopPropagation`・`stopImmediatePropagation` の後、`closeMediaAndThen` と `navigateToTile(1)` を実行（行398–432）。
- 左も同様（行433–446）。同一投稿内の画像インデックスがまったく参照されない。
- したがって複数画像の表示中にも、標準画像送りより投稿間移動を優先する設計になっている。
- 対応案: 通常の左右キーはX標準動作に委ね、投稿間移動は別ショートカットと独自ボタンを使用する。境界処理は実サイト検証後に決定。

### AUD-002 / P1 — 投稿IDと画像IDが未分離 (SOURCE VERIFIED)
- 行128–151: `tileIndexMap` はステータスIDをキーとし、複数タイルが同じ投稿IDなら番号を共有する。
- 投稿内のメディア順序・画像枚数・`photo/N` などを管理する状態がない。
- 対応案: 投稿ID + メディア位置を区別し、表示中の画像と投稿間の移動を別概念として扱う。

### AUD-003 / P1 — DOM差し替え後に参照が古くなる (SOURCE VERIFIED)
- 行139–148: 既知IDが再表示されても `tileNumberMap` の要素参照を更新しない。
- 行301–320: 保存済み要素をそのままクリックするため、DOMが再構成された場合は無効になる可能性。
- 対応案: 要素を永続キャッシュせず、遷移時に接続状態を確認して再探索する。

### AUD-004 / P1 — 番号のリセットが不完全 (SOURCE VERIFIED)
- 行112–122: `resetTileNumbers()` は2個のMapを消すが `globalTileCounter` を1に戻さない。
- アカウント切り替え時に通し番号が継続する可能性がある（行100–109）。

### AUD-005 / P1 — 追加読み込み完了の確認がない (SOURCE VERIFIED)
- 行368–393: `scrollTo()` 実行後に `scroll` 監視を開始。スクロールイベントが取れない場合、コールバック不能。
- 300ms静止で読み込み完了と扱うが、新しいタイルの到着は保証されない。
- 行301–310: 番号上限に達した際は既存の最大番号にクランプされ、同じ投稿を再度開くおそれ。

### AUD-006 / P1 — SPA遷移・周期監視の負荷 (SOURCE VERIFIED)
- 行451–496: URLパスを100ms周期でポーリングし、直前が `/media` の場合だけビューアボタンを追加。
- 行33–46: listitemの全走査は500ms周期。route変化で状態が失われやすく、常駐負荷がある。
- 対応案: 起点のメディアタブの状態を明示的に持ち、MutationObserver/History変更検知を節度ある方式で構成。

### AUD-007 / P1 — 閉じるボタンが日本語UI専用 (SOURCE VERIFIED)
- 行4、277: `button[aria-label='閉じる']` のみに依存。
- Xを英語等に設定している場合、閉じる処理が失敗する可能性がある。

### AUD-008 / P2 — キー入力・動画・ボタン状態の検討不足 (SOURCE VERIFIED)
- 行398以降: フォーカス中の入力欄や動画のシーク操作を避けるガードがない。
- 行231付近: ボタンはdivで生成。行351–359で`disabled`クラスを切り替えるがクリック禁止にはしない。
- CSSに `.disabled` の実効処理がない。アクセシビリティも要改善。

## リスク・変更方針
- これらは静的解析所見。Xの現行DOMでの再現テストは**未実施**。
- 拡張機能本体の操作ロジックは現段階で改変していない。
- まず投稿ID・メディアインデックス・タイルへの参照・ビューア状態を分離し、回帰テストを設計する。
- 提案するキーボード仕様：素の左右＝X標準、Shift+左右＝投稿移動（正式決定前の提案）。

## 追加所見 (2026-10-24)
### AUD-009 / P1 — タイル抽出対象のスコープが広すぎる (SOURCE VERIFIED)
- 行126: ページ全体の `li[role='listitem']` を抽出し、対象プロフィールのメディア一覧コンテナに限定していない。
- 行24: `/status/` ページも定期タイル処理対象になるため、別のリストにある投稿リンクを採番対象として誤認する可能性。
- 別ページに突然飛ぶという利用者レビューの一因となる仮説だが、実サイトでの因果関係は**未確認**。
- 対応案: 起点のメディア一覧を特定し、アカウントと投稿種別を検証したタイルのみ対象にする。
